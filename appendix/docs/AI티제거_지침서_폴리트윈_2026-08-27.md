## 1. 진단 — 왜 티가 나나

### AI는 디자인을 하지 않는다. 다음에 올 가능성이 가장 높은 것을 예측한다.

"모던한 SaaS 사이트"라고만 하면 모델은 학습 데이터에서 가장 흔했던 배치를 내놓는다. 히어로 → 3열 피처 카드 → 후기 → 가격 → CTA. 보라 그라디언트, Inter, `border-radius: 12px`. 이건 모델의 결함이 아니라 **입력이 비어 있을 때의 정상 동작**이다.

그래서 해법도 프롬프트 기교가 아니다. **결정을 미리 내려서 문서로 주는 것**이다. 채팅창을 열기 전에 쓰는 20줄짜리 `DESIGN.md`가 어떤 프롬프트 트릭보다 확실하게 기본값에서 당신을 떼어놓는다.

### 지금 폴리트윈의 상태

이미 잘 하고 있는 게 있다. `UI목업_프롬프트_폴리트윈_2026-08-25.md`는 색·타이포·모션 톤을 랜딩에서 먼저 확정하고 화면을 하나씩 뽑는 순서를 잡아뒀다. 이게 정확히 위에서 말한 "미리 내린 결정"이다. 아래 내용은 그 문서 위에 얹는 것이다.

> ⚠️ **다만 파일이 문제다.**
> `PolyTwin Console.html` 20.4 MB, `polytwin-landing.html` 22.9 MB. 폰트와 이미지가 전부 base64로 단일 HTML에 박혀 있다.
>
> 심사장 와이파이에서 안 열리면 디자인이 아무리 좋아도 끝이다. 폰트는 Google Fonts 링크나 서브셋으로, 이미지는 별도 파일 + WebP로 빼라. 데모 전날이 아니라 지금.

## 2. 검사 — AI가 만들었다는 걸 알려주는 12가지

이 목록은 그대로 `CLAUDE.md`에 "금지" 항목으로 붙여넣으면 된다. 각 항목마다 **대신 무엇을 할지**까지 적어야 효과가 있다. 금지만 하면 모델은 두 번째로 흔한 기본값으로 갈 뿐이다.

| # | 증상 | 대신 |
|---|---|---|
| 01 | **보라→인디고 그라디언트** `#6366F1 → #A855F7` | 단색 표면 + 액센트 1개. 그라디언트를 쓸 거면 같은 색상환 안에서 명도만 5% 차이로. |
| 02 | **Inter / Space Grotesk** 기본 자간 | 주제에 맞는 얼굴을 고른다. 산업 계측 UI라면 IBM Plex, Geist Mono, Söhne 계열. 큰 글자는 자간 음수로. |
| 03 | **3열 균등 피처 카드** | 비대칭. 하나를 크게, 나머지를 작게. 또는 카드를 버리고 목록·표로. |
| 04 | 모든 요소에 **동일한 12px 라운드** | 2px 또는 0. 계층별로 다른 값(컨테이너 8 / 내부 4 / 칩 2). |
| 05 | **모든 섹션 같은 세로 여백** | 여백이 곧 위계다. 섹션마다 다르게, 전환점에 크게. |
| 06 | `transition: all 0.3s ease` | 속성 명시 + `ease-out` 150–250ms. 진입은 빠르게, 이탈은 더 빠르게. |
| 07 | **이모지 아이콘** ✨🚀⚡ | Lucide·Phosphor 같은 아이콘 세트 하나로 통일. 산업 UI면 아예 텍스트 라벨. |
| 08 | **backdrop-blur 유리 카드 남발** | 블러는 실제로 뒤에 뭔가 움직일 때만. 정적 배경 위 블러는 그냥 연한 회색이다. |
| 09 | **순수 회색** `#808080`, `#F5F5F5` | 중립색에 배경 색조를 5–10% 섞는다. 청록 제품이면 회색도 아주 살짝 청색 쪽. |
| 10 | 그림자 하나 `0 4px 6px rgba(0,0,0,.1)` | 3–5단 그림자, 알파 낮게, 색은 검정이 아니라 배경보다 어두운 같은 색조. |
| 11 | **형용사 나열 카피** "Seamlessly integrate…" | 숫자와 명사. "완료율 94.2%", "3축 로봇 3대", "숙련공의 손끝을 데이터로". |
| 12 | **다크모드 = 배경만 검게** | 다크에서는 대비를 낮추고 채도를 올린다. 흰 텍스트는 `#FFF`가 아니라 `#DFE4EA`. |

### 같은 정보, 다른 표본

**✕ 기본값**

```

│ ✨ Real-time Monitoring       │      border-radius: 12px
│ Seamlessly track your robot  │      Inter, box-shadow 0 4px 6px
│ performance with powerful    │

└──────────────────────────────┘
```

**○ 결정을 내린 것**

```
┌──────────────────────────────┐   ← #0E1216, 1px solid #232A31
│ SL-02 · 접촉력                │      border-radius: 2px
│                              │      IBM Plex Mono, tabular-nums
│ 18.4 N                       │
```

## 3. 개념 — Claude에게 지시하려면 당신이 이름을 알아야 한다

"좀 더 세련되게"는 통하지 않는다. "행간 1.5로 줄이고 큰 제목 자간을 −0.03em으로"는 통한다. 아래는 지시어가 되는 개념들이다.

**01. 디자인 토큰 & 스케일**
색 6개, 간격 8pt 배수, 타입은 모듈러 스케일(1.25배). 값을 즉흥으로 쓰지 않는다는 규칙 자체가 일관성을 만든다. CSS 변수로 선언하고 리터럴 색상값 사용 금지.

**02. 타이포그래피**
크기가 커지면 자간과 행간은 줄인다. 본문은 65자 폭. 숫자가 세로로 정렬되는 곳은 전부 `font-variant-numeric: tabular-nums`. 대문자 라벨에는 `letter-spacing` 0.14em 이상.

**03. 색과 그림자**
OKLCH로 다루면 명도를 바꿔도 채도가 유지된다. 그림자는 검정 알파가 아니라 배경 색조를 어둡게 한 값으로, 여러 단으로 쌓는다.

**04. 모션**
진입 `ease-out` 150–250ms, `transform`과 `opacity`만 애니메이트. 목록은 40ms씩 지연시켜 계단식으로. `prefers-reduced-motion` 필수. 스프링은 물리적으로 움직이는 것에만.

**05. 레이아웃과 여백**
여백은 남은 공간이 아니라 위계를 표현하는 도구다. 비대칭 그리드, 광학 정렬(눈에 맞추는 것 ≠ 픽셀에 맞추는 것), `position: sticky` 기반 스크롤 씬.

**06. 정보 밀도**
산업 콘솔은 읽는 게 아니라 훑는 것이다. 본문 13px, 행간 1.4, 촘촘한 표. Linear·Bloomberg 터미널이 기준이지 랜딩 페이지가 아니다. 랜딩(⓪)과 콘솔(①–④)은 밀도가 정반대여야 한다.

**07. 디테일 (craft)**
완성도는 여기서 갈린다. `:focus-visible` 링, `::selection` 색, 커스텀 스크롤바, 빈 상태, 로딩 스켈레톤, 1px 헤어라인, 숫자가 바뀔 때 굴러가는 연출.

**08. 3D · 재질 (three.js)**
형상보다 조명이 중요하다. `roughness` 0.8 → 0.15 전환이 스캔 연출의 핵심이고, HDRI 환경맵 없이는 금속이 금속으로 안 보인다. ACES 톤매핑 + 약한 bloom.

**09. 성능과 접근성**
폰트 서브셋(한글은 특히), 이미지 WebP, LCP 2.5초 이내. 본문 대비 4.5:1. 심사 데모에서 로딩이 5초 걸리면 그 5초가 첫인상이다.

## 4. 절차 — Claude로 만드는 8단계

순서가 실제로 중요하다. 뒤에서 두 단계는 대부분 건너뛰는데, 결과 차이의 절반이 거기서 난다.

**01. DESIGN.md를 먼저 쓴다**
10분. 색 6개, 폰트 2개, 라운드 값, 모션 지속시간, 금지 목록. 이게 나머지 전부를 결정한다.

**02. 레퍼런스를 이미지로 붙여넣는다**
"람보르기니 느낌"이라고 쓰는 것보다 실제 스크린샷 3장을 붙이는 게 압도적으로 정확하다. Claude는 이미지를 읽는다.

**03. Claude Design 캔버스에서 시안을 잡는다**
claude.ai/design에서 아트보드로 여러 안을 뽑고, 클릭해서 직접 고친 뒤 "Claude Code로 전달"로 넘긴다. 디자인 시스템·컴포넌트 구조가 같이 넘어간다.

**04. 한 화면씩, 랜딩부터**
이미 당신 문서에 있는 원칙이다. 5화면을 한 번에 시키면 품질이 떨어진다. ⓪이 톤을 정하고 ①–④가 그걸 밀도 높게 옮긴다.

**05. Claude가 자기 결과를 보게 한다**
Chrome DevTools MCP나 Playwright MCP를 붙이면 Claude가 렌더링된 화면을 스크린샷으로 확인하고 스스로 고친다. 눈 없이 만든 UI와 차이가 크다.

**06. 비평 전용 세션을 따로 연다**
"이 화면에서 AI가 만든 티가 나는 부분 10개를 지적해라. 칭찬 금지." 만든 세션에서 물으면 방어하고, 새 세션에서 물으면 찾아낸다.

**07. 층별로 패스를 돈다**
1차 구조 → 2차 타이포 → 3차 모션 → 4차 디테일. 한 번에 다 고치라고 하면 전부 어중간해진다.

**08. 마지막에 성능과 접근성**
번들 크기, 폰트 서브셋, 대비, 키보드 포커스. 폴리트윈은 여기가 지금 가장 급하다.

### DESIGN.md 시작 템플릿

```markdown
# PolyTwin 디자인 시스템

## 톤
산업용 계측 장비. 람보르기니 공식 사이트의 암전과
Linear 대시보드의 정보 밀도가 한 제품에 공존한다.
"미래적"이 아니라 "정밀한". SF 아님.

## 색 — 리터럴 색상값 금지, 아래 토큰만 사용
--bg-void:    #08090B   # 랜딩 배경
--bg-panel:   #101216   # 콘솔 표면
--line:       #1E232A   # 1px 경계
--text-hi:    #E8EDF2
--text-lo:    #6B7681
--accent:     #4A8FA8   # 톤 낮춘 청록 (형광 시안 아님)
--warn:       #C97A2B   # 경고 전용, 장식 사용 금지

## 타이포
디스플레이: weight 200–300, letter-spacing 0.3em+
본문: 15px / 1.6
데이터: IBM Plex Mono, tabular-nums 필수
한글 본문 자간 0, 영문 대문자 라벨만 0.14em

## 형태
라운드: 컨테이너 4px / 내부 2px / 그 외 0
경계: 1px solid var(--line). 그림자보다 선을 쓴다.

## 모션
진입 200ms ease-out · 이탈 120ms
transform / opacity 외 애니메이트 금지
목록 stagger 40ms
prefers-reduced-motion 반드시 대응

## 금지
보라 그라디언트 · Inter · 이모지 아이콘 · 3열 균등 카드
transition: all · 순수 회색 · backdrop-blur 장식
형용사 카피 ("seamlessly", "powerful", "intuitive")
```

## 5. 설정 — Skill · 도구

Skill은 `SKILL.md` 한 장으로 된 폴더다. 특정 작업을 할 때 Claude가 자동으로 읽어 들이는 전문 지식이라고 보면 된다. 디자인 영역에서 가장 실효가 큰 건 Linear의 디자인 엔지니어 Emil Kowalski가 공개한 세트다.

```bash
# Emil Kowalski 디자인/애니메이션 스킬 11종
npx skills@latest add emilkowalski/skills

# 들어 있는 것 중 쓸 만한 것
emil-design-eng               # 디자인 엔지니어링 전반
animate                       # 커브·지속시간·속성을 제대로 잡은 애니메이션
review-animations             # 기존 애니메이션을 깐깐하게 감사
find-animation-opportunities  # 모션이 필요한 지점 탐색
animation-vocabulary          # 원하는 모션을 말로 설명하는 법
apple-design                  # 애플 인터페이스·모션 원칙
```

Claude Code 안에 이미 들어 있는 것도 있다. `/design`은 아트보드 캔버스를 만들고, `dataviz` 스킬은 차트를 그리기 전에 자동으로 읽힌다 — 폴리트윈은 Chart.js 대시보드가 핵심이므로 **차트 작업 전에 반드시 걸리게 두라**. 프로젝트 규칙은 `CLAUDE.md`에, 되풀이되는 작업은 `.claude/skills/`에 넣는다.

> **3D는 스킬로 안 된다.**
> three.js 조명·재질은 직접 감이 있어야 지시가 가능하다. Three.js Journey를 다 볼 시간이 없다면 최소한 `MeshPhysicalMaterial`의 `roughness` / `metalness` / `clearcoat`과 `RoomEnvironment` 환경맵, `ACESFilmicToneMapping` 이 세 가지만 알고 들어가라. 스캔 연출이 이 위에서 돌아간다.

## 8. 적용 — 폴리트윈, 이번 주에 할 것

일반론 말고 지금 파일에 바로 적용되는 것들이다.

| 순위 | | 내용 |
|---|---|---|
| 1 | ❗ | **번들 20 MB → 2 MB 이하**<br>base64 폰트·이미지를 외부 파일로 분리. 한글 폰트는 서브셋. 이건 디자인 이전에 데모 성공 여부의 문제다. |
| 2 | ❗ | **액센트 색 재선정**<br>`#4FC3F7`는 SF 영화 UI의 기본값이라 "미래적"이 아니라 "AI가 만든"으로 읽힌다. 채도를 20% 낮춘 청록 하나 + 경고 전용 앰버 하나로 줄여라. 실제 계측 장비의 색을 참고. |
| 3 | · | **랜딩과 콘솔의 밀도를 벌린다**<br>⓪은 한 화면에 문장 하나, ①–④는 13px에 촘촘한 표. 지금 문서의 원칙이 맞다. 실행에서 콘솔이 랜딩처럼 헐거워지지 않게. |
| 4 | · | **모든 수치에 tabular-nums**<br>완료율·접촉비율·평균힘·제거량. 숫자가 실시간으로 바뀌는데 자리가 흔들리면 그 한 가지로 아마추어처럼 보인다. |
| 5 | · | **스캔 시퀀스를 무한 루프에서 빼라**<br>8초 루프는 두 번째 재생부터 배경 소음이 된다. 1회 재생 후 유광 상태로 정지, 스크롤이나 클릭으로 재생. 심사위원이 설명하는 동안 화면이 계속 깜빡이지 않는다. |
| 6 | · | **차체는 GLB 하나로**<br>박스·실린더 조합은 조명이 좋아도 한계가 있다. 저폴리 차량 모델 하나 얹고 환경맵 + ACES 톤매핑을 쓰는 편이 시간 대비 결과가 훨씬 낫다. |
| 7 | · | **비평 세션 한 번**<br>새 대화를 열고: "폴리트윈 랜딩 스크린샷이다. AI가 만든 티가 나는 부분 10개를 지적하고 각각 구체적 CSS 수정안을 달아라. 칭찬 금지." |
