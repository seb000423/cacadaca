# 폰트 크기 실측 보고서 (2026-09-01)

"전반적으로 폰트를 키워야 하나"에 답하기 위해 **23개 화면 전부를 헤드리스
Chrome 으로 열어 실제 렌더된 글자 크기를 실측**했다. 감이 아니라 값으로 정한다.

---

## 결론

**전반적으로 키우는 것은 반대다. 세 덩어리가 각각 다른 문제다.**

| | 판단 |
|---|---|
| **작업 화면** (① 콘솔 · ③④ 라이브러리 · 저장 · ② 모니터링 · 계정 관리) | **키운다.** `DESIGN.md` 가 정한 13px 규격보다 한 단계 작게 구현돼 있다 |
| **서브 페이지** (`sub.html` 16종) | **도해 안만 키운다.** 본문·리드·제목은 이미 적정하다 |
| **랜딩** (`index.html`) | **손대지 않는다.** 키우면 ⓪과 ①–④의 밀도 차이가 사라진다 |

그리고 크기보다 심각한 문제를 하나 찾았다 — **SVG 도해에 척도가 없다** (§5).

## 1. 실측 방법

재현하려면 로컬 서버를 띄우고 아래를 돌린다. 로그인이 필요한 화면이 있으므로
세션 쿠키를 먼저 받아 CDP 로 심는다.

```bash
node server/server.js

# 세션 쿠키
curl -s -c cookies.txt -X POST http://127.0.0.1:8000/api/login \
  -H "Content-Type: application/json" \
  -d '{"loginId":"admin","password":"polytwin2026"}'
```

각 화면에서 **텍스트 노드를 전부 순회**하며 부모의 computed `font-size` 를
읽고, **글자 수로 가중**해 집계했다. 요소 개수로 세면 짧은 라벨이 긴 문단과
같은 무게가 되어 그림이 왜곡된다.

- 뷰포트 **1488×795** (`--window-size=1512,950` 기준 실제 값)
- `display:none` · `visibility:hidden` · 크기 0 인 요소는 제외
- `<script>` · `<style>` 안은 제외

> **주의 — 캡처가 흰 화면으로 나올 때.** `Emulation.setDeviceMetricsOverride`
> 를 쓰거나 `Page.captureScreenshot` 의 `clip` 을 뷰포트보다 크게 주면
> 렌더가 통째로 비어 나온다. `--window-size` 만 쓰고 `clip` 없이 찍어라.
> 그리고 **한 브라우저 인스턴스로 여러 번 `Page.navigate` 하지 마라** —
> `Page.loadEventFired` 가 앞 페이지 것과 섞여 이전 화면을 찍는다.
> 화면마다 브라우저를 새로 띄우는 편이 확실하다.

## 4. 무엇을 키우고 무엇을 유지하나

판단 기준은 **"짧은 식별자인가, 읽어야 하는 문장인가"** 다. 크기만 보면
안 된다 — 11px 라벨과 11px 문단은 같은 11px라도 판단이 정반대다.

### 4.1 키운다 — 문장인데 라벨 크기로 설정된 것

| 대상 | 현재 → 제안 | 이유 |
|---|---|---|
| `.p-fig figcaption` · `.lead figcaption` | 11 → **13px** | 도해의 설명이다. 옆 본문이 15px 인데 11px 면 각주로 읽힌다 |
| `.tb th, .tb td` | 12 → **13px** | DESIGN.md "수치(표) 13px" |
| `.gen__d` `.gen__o` `.flow__d` `.cmp__a` `.cmp__b` `.cal__k` `.sc__d` `.mul__v` `.rl__eq` `.gantt__l` `.pl__t` | 12 → **13px** | 전부 도해 안의 **문장**이다 |
| `.tb thead th` · `.st` · `.cmp__h span` | 10 → **11px** | 라벨 규격(11px)에 맞춘다 |
| `.tb caption` · `.rl__curve p` · `.cal__d` · `.mul__k` | 11 → **12px** | 표·도해의 부연이다 |
| 번들 3화면(`Console`·`Library`·`Save`) 본문·표 | 11 → **13px** | DESIGN.md 규격. `*-src/repack.py` 경유 |
| `monitor.html` KPI 캡션·이벤트 로그 | 10–11 → **12–13px** | 엔지니어가 실제로 읽는 값이다 |
| `admin.html` 표 | 12 → **13px** | 계정 상태를 읽는 표다 |

### 4.2 유지한다 — 마이크로 라벨

```

.hdr__role  .post time  .rail span  .menu-side h2  .menu-page h2
.ch__k small  .ch__v small  .lg  .lang  .ft small  .ft__links a  .menu-foot
```

전부 **짧고, 대문자거나 식별자고, 자간이 들어간** 것들이다. DESIGN.md 의
`라벨·단위 11px / 500 / 0.12em 대문자` 규격에 맞고, 이걸 키우면 본문과
구별이 사라져 위계가 무너진다. 단위 10px 도 "값은 크게, 단위는 작게"
규칙대로다.

### 4.3 랜딩은 그대로 둔다

| 역할 | 현재 |
|---|---|
| `h1` | `clamp(30px, 4.6vw, 54px)` |
| `h2` | 38px |
| `h3` | 26px |
| `.hero__sub` | 18px |

## 5. 크기보다 심각한 문제 — SVG 도해에 척도가 없다

실측하다 나온 진짜 발견이다.

**SVG 안의 글자는 viewBox 확대율만큼 커진다.** 그래서 CSS 에 적힌 px 와
화면에 보이는 크기가 다르다. 이 프로젝트의 도해들은 viewBox 폭이 제각각이라
같은 규칙이 화면에서 전혀 다른 크기로 나온다.

| 도해 | viewBox → 렌더 폭 | 배율 | CSS | **화면 실측** |
|---|---|---:|---:|---:|
| `pl` (도장면 단면) | 400 → 742px | 1.85 | 11px | **20.4px** |
| `iso` (ISO 대역) | 480 → 742px | 1.55 | 11px | **17.0px** |
| `aging` (연령 막대) | 480 → 742px | 1.55 | 9px | **13.9px** |
| `cagr` (성장률) | 960 → 1110px | 1.16 | 9px | **10.4px** |

**같은 `.bars .t-ax` 규칙이 화면에서 10.4px 부터 20.4px 까지, 2배 차이로
렌더된다.** `pl` 의 라벨(20.4px)은 본문(15px)보다 크고, `cagr` 의 축
숫자(10.4px)는 캡션보다 작다.

### 여기서 CSS px 를 올리면 더 나빠진다

`.bars .t-ax` 를 9 → 11px 로 올리면

- `cagr` 은 10.4 → 12.8px (나아짐)
- `aging` 은 13.9 → **17.0px** (본문보다 커짐 — 망가짐)

### 고칠 방향

**크기를 올리는 게 아니라 viewBox 를 통일한다.** 배율이 1에 가까워지면
그때부터 CSS px 가 곧 화면 px 가 되고, 도해 전체에 하나의 척도가 선다.

| 자리 | 렌더 폭 | 제안 viewBox 폭 | 배율 |
|---|---:|---:|---:|
| 스텝 도해 (`.p-fig`) | ~742px | **740** | 1.00 |
| 띠 도해 (`.p-fig--wide`) | ~1110px | **1120** | 0.99 |

통일한 뒤에 SVG 안 글자를 라벨 11px · 값 13px 로 두면 HTML 쪽과 같은
척도가 된다.

대상: `.bars` (`aging` · `cagr`), `.pl` (`paint`), `.iso` (`iso15066`),
`.gantt` (`cycle`), `.rl__curve` (`rlpolicy`).

## 6. 크기 문제가 아닌 것 — 라이브러리 카드 폭

`③④ 라이브러리` 의 9px 텍스트(스파크라인 캡션 `08-27 10:26 스윕 최적`,
`접촉력 1.4–4.3 N`)는 **글자가 작은 게 아니라 카드가 좁아서 눌린 것**이다.

1488px 폭에서 카드가 4열이라 하나가 약 310px 다.

**3열로 줄이면 글자를 키우지 않아도 읽힌다.** 크기 조정보다 이쪽이 먼저다.

## 10. 3차 상향 — +1px 은 인지되지 않는다

§9 반영 후에도 "바꾼 거 맞냐, 안 보인다"는 지적을 받았다. 두 가지가 겹쳤다.

**(1) 배포본이 옛날 것이었다.** 수정은 로컬 파일에만 있었고 커밋·푸시를
안 한 상태였다. Vercel 은 GitHub 에서 빌드하므로 배포 주소에는 8/31 판이
그대로 떠 있었다. `.vercel/output/static/` 안의 사본도 13px 옛날 것이다
(gitignore 대상이라 배포에는 안 쓰이지만, `vercel dev` 로 보면 이게 뜬다).

**(2) 더 근본적으로 — +1px 은 눈으로 구분되지 않는다.** 13 → 14px 은 7.7%다.
나란히 놓고 재야 보이는 차이를 "키웠다"고 보고한 것이 잘못이었다.
**작업 화면 본문을 16px 로, 한 번에 올렸다** (원래 13px 대비 +23%).

| 화면 | 최초 | §8 | §9 | **§10 (현재)** |
|---|---:|---:|---:|---:|

## 11. 일괄 스크립트가 놓친 것 — `clamp()` 와 드로어 메뉴

§10 이후에도 **드로어 메뉴는 그대로였다.** 원인은 두 가지다.

**(1) 정규식이 `clamp()` 를 못 잡았다.** 상향 스크립트는
`font-size:\s*([0-9.]+)px` 로만 매칭해서, `font-size: clamp(22px, 3vw, 34px)`
같은 선언 **15곳을 통째로 건너뛰었다.** 메뉴 대제목(COMPANY·SOLUTION),
랜딩 h1·h2, 서브 페이지 제목이 전부 여기 있다.
다행히 이들은 22–68px 라 원래 충분히 컸다 — 그래서 눈에 안 띄었을 뿐,
**일괄 치환은 신뢰할 수 없다**는 사실이 그대로 남는다.

**(2) 메뉴 하위 링크는 +1px 만 올라가 있었다.** `.m-sub a` 16 → 17px.
34px 대제목 밑에 17px 링크가 붙으니 "하나도 안 바뀐" 화면이 됐다.

메뉴만 다시 잡았다 (git HEAD 판과 A/B 로 실측):

| 메뉴 요소 | 수정 전 | **현재** |
|---|---:|---:|
| 대제목 (COMPANY·SOLUTION) | 34px | 34px (원래 충분) |
| **하위 링크 (Our goal · 폴리싱)** | **16px** | **21px** |
| 바로가기 카드 | 16px | 19px |
| 바로가기 제목 | 11px | 14px |
| 푸터 한 줄 | 12px | 15px |

### 검증하다 걸린 함정 두 개

- **언어 링크(`.lang a`)는 `href="?lang=en"` 이라 클릭하면 페이지가 이동한다.**
  스크립트로 클릭하면 DOM 이 리셋돼 엉뚱한 상태를 재게 된다. 언어는 URL 로 준다.
- **`_cmp_*.html` 같은 비교본은 `PUBLIC_PAGES` 밖이라 세션이 없으면
  302 로 `index.html` 에 튕긴다.** 그래서 수정 전·후가 똑같은 값으로 나왔다.
  비교 렌더에는 **반드시 세션 쿠키를 심고, `location.pathname` 을 찍어
  실제로 그 페이지에 도착했는지 확인**해야 한다.

남은 12px 은 사이드 레일 세로 글자(`PT` · `04 LIBRARY`), 카드 배지,
태그 칩뿐이다 — 전부 §4.2 의 유지 대상이다.
